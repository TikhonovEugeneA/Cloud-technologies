## Задание:
Запустить контейнер на базе образа практической работы 3 на кластере Kubernetes. Организовать и проверить сетевой доступ к серверу как внутри кластера, так и из вне.

## Команды для выполнения работы

### Присвоить образу тэг
docker tag <имя_образа> <логин_dockerhub>/<имя образа>:тэг.

#### Пример

docker tag image3 emantro/image3:latest

#### Пояснение

- docker tag - дает существующему образу дополнительное имя.

- Слева - источник (изначальный образ)

- Справа - приемник (должное название для Docker Hub)

### Загрузить образ в репозиторий
docker push emantro/image3:latest

### Запустить модуль с контейнеризированным приложением на базе указанного модуля образа Docker с открытием указанного порта
kubectl run practice4 --image=emantro/image3 --port=8080

### Зайти внутрь контейнера
kubectl exec -it practice4 -- sh

### Запустить туннель между локальной машиной и изолированной локальной сетью кластера
minikube service practice4 --url

#### Пояснение
В ответе будет url адрес, с помощью которого можно извне, например, из браузера послать запрос к серверу в кластере

### Узнать подробную информацию о модуле
kubectl describe pods

### Создать сервис типа NodePort
kubectl expose pod <имя_модуля> --type=NodePort --port=8080

#### Пояснение
- NodePort - сервис, через порт которого можно получить доступ к модулю или развертыванию с любого ПК как внутри кластера так и из вне. Номер такого порта будет лежать между 30000 - 32000;
- Но чтобы получить доступ извне кластера нужно выполнить команду: minikube service practice4 --url

### Зайти внутрь контейнера minikube
minikube ssh 

#### Пояснение
Docker-контейнер, внутри которого работает linux с k8s. Этот контейнер и есть узел кластера (нода minikube). Команда же открывает SSH-сессию внутрь этого контейнера. То есть открывается командная строка внутри узла кластера.

### Проверить доступ изнутри кластера с помощью url запрос к серверу
- curl <pod-IP>:<открытый_порт_модуля> — обращение к конкретному модулю напрямую;
- curl <ClusterIP>:<port> — обращение к сервису через виртуальный IP (порт, на который сервис принимает трафик внутри кластера);
- curl <IP любого хоста в кластере>:<NodePort-port> — обращение к IP адресу любого хоста в кластере; указав порт NodePort, попадаем на модуль, с которым связан этот NodePort;
